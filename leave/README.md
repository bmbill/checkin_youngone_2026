# 卓青營 學員請假／銷假系統

紙本二聯單的電子化版本。跟報到系統（`index.html`、`care.html`、`Api.gs`）是**兩套獨立的系統**：
不同的網址、不同的資料庫、不同的通行碼。兩邊唯一的交集是請假系統會定時去**讀**一份
報到名單當作學員清單，從頭到尾不會寫回報到那份試算表。

## 流程

```
關懷員填單 ──▶ 等待簽核 ──▶ 大組長／副大組長簽核 ──▶ 請假中 ──▶ 關懷員填實際回來時間 ──▶ 完成銷假
                  │                    │
                  │                    └──▶ 已退回（要填原因）──▶ 關懷員改完重送
                  └──▶ 已取消（關懷員自己取消）
```

行政中心全程唯讀，看得到四種狀態的全部單子，並可在服務台代為銷假。

## 四種身分

| 身分 | 能做什麼 | 不能做什麼 |
|---|---|---|
| 關懷員 `care` | 填單、銷假（**只限自己開的單**） | 簽核、看別人的單 |
| 大組長 `lead` | 簽核、退回 | 填單、銷假 |
| 副大組長 `deputy` | 簽核、退回 | 填單、銷假 |
| 行政中心 `admin` | 看全部、代為銷假、作廢任何單、同步名單、匯出 | 簽核、填單 |

大組長和副大組長各自一組通行碼、可以簽核**全部**的單子；登入時填的名字會記進簽核紀錄，
所以事後查得到每一張單是誰簽的。

## 關懷員之間怎麼區隔

同一組關懷員通行碼是大家共用的，區隔靠**登入時打的姓名**：

* 你只看得到**自己這個名字**開出來的單，別人的單連資料都不會傳到你的手機上
* 修改、取消、銷假也只能動自己開的單
* 「關懷員」欄位在填單畫面是鎖住的，就是你登入時打的名字

代價很直接：**名字打得不一樣就會看不到自己的單。**「林安」和「林 安」在系統裡是兩個人。
姓名存在那支手機裡，所以同一支手機不會變；換手機或重新登入時要打成一樣。
打錯了就登出、用正確的打法重新登入即可，單子不會消失。

真的卡住時（關懷員換班了、手機沒電、名字怎麼都對不上），**行政中心可以代為銷假**——
這是刻意留的逃生門，否則那張單會永遠掛在「請假中」沒有人能收尾。

權限是擋在**資料庫**裡的，不是靠前端少放幾顆按鈕 —— 前端是公開的靜態網頁，
任何人都能自己組請求。拿關懷員的碼去呼叫簽核，資料庫會直接拒絕。

# 安裝

## 1. 建立 Supabase 專案並套用結構

1. 到 [supabase.com](https://supabase.com) 註冊（免費，可以用 GitHub 帳號登入），
   建一個新專案，區域選 **Northeast Asia (Tokyo)** —— 離台灣最近，反應最快。
2. 後台左邊 **SQL Editor** → New query → 把 `supabase/schema.sql` **整份**貼上 → Run。
3. 應該會看到 `Success`。這份 SQL 可以重複執行，不會弄掉已經有的資料。

## 2. 設定四組通行碼

還在 SQL Editor，把 `xxxx` 換成你們要用的碼（**四組都要不一樣，也不要跟報到系統的重複**）：

```sql
select lv_set_code('care',   '關懷員',   'xxxx');
select lv_set_code('lead',   '大組長',   'xxxx');
select lv_set_code('deputy', '副大組長', 'xxxx');
select lv_set_code('admin',  '行政中心', 'xxxx');
```

通行碼只以 bcrypt 雜湊的形式存在資料庫，**不會出現在任何檔案裡**。
之後要改就再跑一次同一句。

跑完順手確認權限有收乾淨（應該只列出 12 支 `lv_` 開頭的函式，
不能出現 `lv_set_code`、`lv_who`、`lv_all_json`、`lv_targets`、`lv_overdue_jobs`）：

```sql
select p.oid::regprocedure
  from pg_proc p join pg_namespace n on n.oid = p.pronamespace
 where n.nspname = 'public' and p.proname like 'lv\_%'
   and has_function_privilege('anon', p.oid, 'EXECUTE');
```

## 3. 填 `leave/config.js`

後台 **Project Settings → API**，把兩個值填進 `leave/config.js`：

```js
url:     'https://xxxxxxxx.supabase.co',
anonKey: 'eyJhbGciOi……',
```

`anonKey` 是公開的沒關係 —— 資料庫裡每一張表對它都是零權限，
能呼叫的只有 12 支函式，而每一支的第一行都是驗通行碼。

## 4. 讓請假系統讀得到報到名單

**改 `Api.gs`（報到系統那支）：**已經幫你加好了，只要填一個值。
`API_CONFIG.LEAVE_TOKEN` 填一組新的字串（唯讀專用，跟另外兩組都不一樣），
然後在 Apps Script 裡 **重新部署**（部署 → 管理部署 → 編輯 → 版本選「新版本」→ 部署）。

> 這個改動只加不改：新增一個 token 和一個 `getRoster` 動作，
> 原本 staff／care 兩條路徑一個字都沒動。`getRoster` 只回
> 組別／姓名／預排房號／錄取編號四個欄位，整支函式沒有任何寫入。

## 5. 部署兩支 Edge Function

後台 **Edge Functions → Deploy a new function**，可以直接在網頁上貼程式碼。
建兩支，名字要**完全一樣**：

| 名字 | 內容來源 | 做什麼 |
|---|---|---|
| `sync-roster` | `supabase/functions/sync-roster/index.ts` | 去報到名單抄一份學員清單 |
| `push` | `supabase/functions/push/index.ts` | 發鎖屏推播 |

如果你的後台沒有網頁編輯器，用 CLI（需要 Node.js，這台電腦已經有了）：

```bash
npx supabase login
npx supabase link --project-ref xxxxxxxx
npx supabase functions deploy sync-roster
npx supabase functions deploy push
```

然後在 **Edge Functions → Secrets** 加這幾個（`SUPABASE_URL` 和
`SUPABASE_SERVICE_ROLE_KEY` 平台會自動給，不用自己設）：

| 名稱 | 值 |
|---|---|
| `ROSTER_API_URL` | 報到系統 Apps Script 的部署網址（`index.html` 裡的 `API_URL`） |
| `ROSTER_TOKEN` | 上一步在 `Api.gs` 設的 `LEAVE_TOKEN` |
| `VAPID_PUBLIC_KEY` | 下一步產生 |
| `VAPID_PRIVATE_KEY` | 下一步產生（**絕對不要進 git**） |
| `VAPID_SUBJECT` | `mailto:你的信箱` |

## 6. 產生推播金鑰

```bash
node tools/gen_vapid.mjs
```

* 公鑰 → `leave/config.js` 的 `vapidPublicKey`
* 私鑰 → 上面的 `VAPID_PRIVATE_KEY`

**營期期間不要重跑這支**：換金鑰等於把所有訂閱作廢，每支手機都要重新開啟推播一次。

想確認加密邏輯沒問題（不需要真手機）：

```bash
node tools/test_push_crypto.mjs
```

## 7. 告訴系統網頁在哪裡

推播被點開時要知道要開哪個網址。SQL Editor 跑一次：

```sql
select lv_set('app_url', 'https://bmbill.github.io/checkin_youngone_2026/leave/');
```

## 8. 推上 GitHub Pages，然後同步名單

`git push` 之後，網址是 `https://bmbill.github.io/checkin_youngone_2026/leave/`。

用**關懷員**的碼登入就好——**名單會自己下載**，不必去點任何東西：

* 手機上一份名單都沒有 → 開啟時擋著畫面等它抓完（沒名單就填不了單）。
  第一次要幾秒，因為 Edge Function 要冷啟動、Apps Script 本身也慢。
  失敗的話畫面上會留著失敗原因和一顆「再試一次」
* 有名單但超過 15 分鐘 → 舊名單先用，背景靜靜換新，不打斷任何人
* 名單還新 → 完全不動，登入不會因此變慢

「⋯」→「同步學員名單」只留在**行政中心**的選單裡，給「報到名單剛改過、要馬上生效」用。
關懷員的選單裡沒有這一項 —— 他不必知道名單這件事存在。
自動下載失敗也不會擋住任何人：手上有舊名單就照樣填單，
完全沒有名單時卡片上會寫出失敗原因和一顆「再試一次」。

## 怎麼測名單自動讀取

自動讀取只在兩種情況觸發，所以要測就得先製造那個情況（清手機的快取沒有用 ——
名單是跟著登入一起從資料庫傳下來的，不是存在手機裡）：

**測「第一次、完全沒名單」那條路**（會擋著畫面等）：
Supabase 後台 → Table Editor → `lv_students` → 全選刪除 → 回請假系統重新登入。
應該看到「下載學員名單…」的覆蓋層停幾秒，然後填單畫面直接可用。

**測「名單過期、背景更新」那條路**（畫面上不會有任何動靜，這是刻意的）：
SQL Editor 跑

```sql
update lv_students set updated_at = now() - interval '30 minutes';
```

然後重新載入請假系統。看不到任何提示是正確的；驗證方式是回 SQL Editor 跑
`select max(updated_at) from lv_students;`，時間會變回剛剛。

## 名單多久更新一次

**沒有排程，是「關懷員的 app 每次跟伺服器說話時順便檢查」**——
登入時檢查，之後每 8 秒的輪詢也會檢查（所以頁面一直開著也會換到新名單）：

| 資料庫裡的名單 | 行為 |
|---|---|
| 空的 | 擋著畫面抓一次 |
| 超過 15 分鐘 | 背景更新（那位關懷員不會感覺到） |
| 不到 15 分鐘 | 不動 |

所以實際上是「每 15 分鐘最多一次」。跟有幾支手機無關：過期之後只有第一個檢查到的人
會真的去抓，抓完所有人看到的就都是新的。同步要好幾秒，而輪詢是 8 秒一次，
所以前一次還沒回來時不會再發第二次。

沒有任何關懷員開著 app 就不會更新 —— 這是刻意的，不然整晚都在打報到系統的 Apps Script。

**報到名單剛改完要馬上生效**：用行政中心登入 → 「⋯」→ 同步學員名單。

要改成固定排程也可以（跟逾時提醒同一個地方）：後台 Integrations → Cron，
每小時呼叫 Edge Function `sync-roster`，body 填行政中心的通行碼
`{ "code": "行政中心的碼" }`。不過營期裡名單一天到頭改不了幾次，
6 小時那一版通常就夠，而且不必把通行碼放進排程設定裡。

## 作廢（只有行政中心）

誤開的單、營期前的測試單，需要一個乾淨的出口。行政中心在任何單子上都有「作廢這張單」，
**必填原因**，狀態變成「已取消」。

最需要它的情況是這個：關懷員誤開一張單、大組長已經按下同意放行（狀態「請假中」）。
關懷員自己不能取消已放行的單，沒有作廢的話唯一的出路是按「銷假」——
那會留下一筆學員根本沒出去過的「完成銷假」紀錄。

**作廢不是刪除。** 資料完整留著，紀錄欄會寫「行政中心 某某 作廢（原狀態：請假中）：原因」，
匯出的 Excel 也看得到，另有一欄「作廢原因」。這跟報到系統關懷員備註的做法一致 ——
劃掉，不是拿掉。理由很實際：學員外出期間萬一出事，那張單是唯一的書面證據，
真的把那一列拿掉之後，誰在幾點、為什麼刪的，沒有任何人查得回來。

作廢後那位學員就可以重新開一張新的單（系統只擋「等待簽核」和「請假中」的重複開單）。

## 清掉測試單（營期前）

作廢後那張單還是會出現在「已結束」和匯出裡。測完想把場地掃乾淨，到 SQL Editor 跑：

```sql
select lv_reset_leaves('清空所有請假單');
```

會回報清掉幾張，並且**把單號歸零**——營期第一張真正的單會是 L0001。
忘記歸零的話第一張會是 L0008 之類的，對照紙本時很容易讓人以為前面幾張不見了。

那句「清空所有請假單」要一字不差地打進去。這是不可回復的操作，
營期期間有人貼錯一段 SQL 就全沒了；多打一句話，就不會是手滑能造成的結果。

只想刪掉某一張（例如剛剛那張測試單）：

```sql
delete from lv_leaves where no = 'L0001';
```

或到 Table Editor → `lv_leaves` → 勾那一列 → 刪除。

推播裝置和推播紀錄都不會被上面任何一句動到 —— 清掉裝置的話每支手機都要重新開一次推播，
那跟「清測試單」是兩件不同的事。真的要清：`delete from lv_devices;`、`delete from lv_pushlog;`

# 匯出 Excel

**大組長、副大組長、行政中心**：右上角「⋯」→「匯出 Excel（全部 N 張單）」。

產出一個 `.xlsx`，20 欄，一列一張單，含全部五種狀態（等待簽核／請假中／完成銷假／已退回／已取消），
已經套好凍結標題列和自動篩選，在 Excel 裡可以直接依狀態或組別篩。多一欄「逾時分鐘」——
已銷假的用實際回來時間算，還在外面的用當下時間算，行政中心事後檢視不必自己兩個時間相減。

刻意產真正的 `.xlsx` 而不是 CSV，原因是 **Excel 會把 `0912345678` 當成數字、把開頭那個 0 吃掉**。
請假單上的電話就是要拿來打的，被吃掉等於白存。`.xlsx` 可以把電話和房號明確標成文字。
萬一現場連不到產檔用的元件（那是一支外部 JS），系統會自動退回 CSV，並在電話欄用 `="…"` 保住那個 0。

匯出的是「你這個身分看得到的單」。關懷員只看得到自己開的單，所以匯出功能不給關懷員 ——
要全場的資料請用上面那三種身分。

> 用電腦匯出最保險。iPhone 從主畫面圖示開的 PWA 有時候擋下載，
> 那時候改用 Safari 開同一個網址就會正常。

# 每支手機要做的事

**關懷員不需要開推播**，所以下面只有大組長、副大組長、行政中心那幾支手機要設。
關懷員送出單子時人就站在學員旁邊看著螢幕，簽核結果 8 秒內就會跳出來；
而 iPhone 那套「加入主畫面」的手續又最容易漏掉。少設幾十支手機，
營期前的準備工作就少一大半。

## Android（Chrome）

登入 → 按「開啟推播」→ 允許通知。完成。

## iPhone（Safari）—— 一定要照這個順序

iOS 不讓「在 Safari 裡直接開的網頁」發通知，**必須先加到主畫面**：

1. Safari 開請假系統的網址
2. 點下方的「分享」→「加入主畫面」
3. **關掉 Safari**，改從主畫面上新出現的圖示打開
4. 登入 → 按「開啟推播」→ 允許通知

漏掉第 3 步的話，按「開啟推播」會失敗或看起來成功卻收不到，而且**不會有任何錯誤訊息**。
營期前請一支一支確認過，最保險的驗證方式是：請人送一張測試單，看手機鎖屏會不會跳出來。

需要 iOS 16.4 以上。太舊的手機收不到鎖屏通知，但**頁面開著的時候一樣會響鈴**。

# 通知有三層，不要只依賴一層

| 層 | 什麼時候有用 | 靠什麼 |
|---|---|---|
| 即時訂閱 | 頁面開著 → 新單當場跳出來 | Supabase Realtime |
| 輪詢 | 頁面開著、訂閱斷線也能用 | 每 8 秒問一次（訂閱通了放慢到 30 秒） |
| 鎖屏推播 | 頁面關著、手機鎖著 | Web Push |

推播失敗、CDN 被擋、金鑰設錯 —— 系統都還是能正常用，只是通知慢一點。
**營期現場最可靠的用法還是「簽核的人把頁面留在前景」。**

# 選用：逾時未回營自動提醒

學員超過預計回來時間 30 分鐘還沒銷假時，自動推一則給行政中心和關懷員（每張單只提醒一次）。

後台 **Integrations → Cron** → 新增排程 → 每 10 分鐘 → 目標選 Edge Function `push`，
request body 填：

```json
{ "mode": "overdue" }
```

沒設這個也沒關係，頁面上本來就會用紅字標出「已逾時 25 分」，
行政中心的「請假中」頁籤最上面也會列出所有逾時的人。

# 選用：防止免費專案被暫停

Supabase 免費專案**閒置 7 天會自動暫停**，暫停後要人工到後台按 Restore。
`.github/workflows/keep-supabase-awake.yml` 每三天戳一下就不會發生。
用法見那個檔案開頭的說明（要設兩個 repo secret）。

**營期前一天務必自己開一次網頁確認連得上。**

# 資料在哪裡

後台 **Table Editor**：

| 表 | 內容 |
|---|---|
| `lv_單子`（檢視） | 給人看的請假單，時間已經換成台北時間、欄名中文，可以直接匯出 CSV |
| `lv_leaves` | 請假單原始資料（時間是 UTC，會跟台灣差 8 小時，看 `lv_單子` 比較準）。營期前要把測試單徹底清掉就是刪這裡的列 |
| `lv_students` | 從報到名單抄過來的學員清單 |
| `lv_devices` | 哪些手機開了推播 |
| `lv_pushlog` | 每一次推播送給幾支、失敗原因 —— 回答「我為什麼沒收到通知」 |

每張單的「紀錄」欄記著完整經過：誰幾點建立、誰幾點簽核、誰幾點銷假、被誰退回過。
一律只增不改，事後追得回來。

# 現場出問題

| 症狀 | 先看這裡 |
|---|---|
